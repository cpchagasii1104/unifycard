# Canonical Category Tree — Single Root, Multiple Contexts

## Objetivo
- Definir a árvore de categorias como linguagem universal do sistema
- Eliminar interpretações divergentes

## Raiz Canônica
- Existe UMA única raiz lógica: categories (core)
- Não existem múltiplas raízes por domínio

## Contextos (galhos principais)
- professional
- interest
- learning
- health
- education
- company
- person
- government
- infrastructure
- economy

## Regras Estruturais
- Context define domínio semântico, não hierarquia física
- Uma categoria pode existir em apenas UM contexto
- Categorias nunca cruzam contextos
- Context é obrigatório em toda leitura

## Tenant
- Tenant não cria nova árvore
- Tenant define permissões e visibilidade
- Tenant nunca altera a raiz

## O que é PROIBIDO
- Criar múltiplas árvores
- Criar roots por domínio
- Criar categories_government, categories_marketplace etc.
- Ler categorias sem context

## Nota de Governança
- Governo é uma visão soberana da mesma árvore
- Cooperativismo, mercado e indivíduo compartilham a linguagem
